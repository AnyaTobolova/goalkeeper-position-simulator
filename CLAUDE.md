# CLAUDE.md — правила работы над проектом «Где стоять вратарю?»

Этот файл — для ИИ-ассистента (Claude / Codex). Открой его первым, чтобы сразу понять проект и как в нём работать. Идентичная копия — в `AGENTS.md` (держать синхронными). Общие правила пользователя — в глобальном `~/.claude/CLAUDE.md`; здесь только специфика проекта.

## Что это

Обучающий 2D-симулятор позиционирования футбольного вратаря для ребёнка ~9 лет и его друзей. Личный проект без коммерции. Развёрнут на `https://keeper.anyatobolova.ru`.

Полная картина — в `docs/Обзор_проекта.md`. Методика — в `docs/Методическая_база_вратаря.md`. Сценарии и логика оценки — в `docs/Сценарии_и_правильные_решения.md`.

## Стек и структура

- Vite + React 19 + TypeScript, статическое SPA, без бэкенда. SVG-поле, Web Audio, localStorage, PWA.
- Доменная логика (чистые функции, покрыты тестами): `src/domain/` — `types, levels, presets, scenarios, positionZones, geometry, evaluate, feedback, variation, badges, rulesQuiz`.
- UI: `src/App.tsx` (главный экран и циклы), `src/components/*`, `src/sounds.ts`, `src/storage.ts`, `src/styles.css`.
- Тесты: `src/domain/__tests__/methodology.test.ts`.

## Команды

```bash
npm run dev      # локальный запуск

npm run build    # tsc + vite build
```

Деплой (обновление прода): `npm run build` → `scp dist/*` на VPS в `/srv/keeper/`. Подробно — `docs/Обслуживание_и_деплой.md`.

## Главный приоритет: методическая правильность

Игра учит ребёнка вратарским правилам — неверная подсказка закрепляет плохой навык. Любая правка оценочной логики должна сохранять футбольную корректность:

- Оценка позиции — в `src/domain/evaluate.ts` и `src/domain/positionZones.ts`. Зоны строятся алгоритмически (линия мяча, глубина, ближний угол, корпус), а не как заранее нарисованные прямоугольники.
- Есть методический регресс-тест: инвариант «идеальная точка каждого уровня даёт Отлично» для всех сценариев + проверки корпуса, глубины от размера ворот, зеркал, пенальти, штрафных. **Не ослаблять тесты ради прохождения — чинить причину.**
- Ключевые методические факты закреплены: корпус к мячу обязателен для «Отлично»; глубина масштабируется от размера ворот; стандарты (угловые/навесы/штрафные/пенальти) заданы целью в координатах ворот (`goalTarget`); пенальти — единственное правило игры «нога на линии».

## Что нельзя ломать

- **Тесты** (`npm run test`) — зелёные перед каждым коммитом.
- **Соседние сайты на VPS.** На `62.113.111.4` через общий Caddy работают другие проекты владельца (n8n, supabase, api, app, academy). Правки Caddy — только аддитивно, с бэкапом, `caddy validate` и `systemctl reload` (не restart). Nginx не ставить — конфликт портов с Caddy.
- **Секреты.** `ssh.txt` и любые ключи не коммитить (защищено `.gitignore`).
- **GitHub Pages** закрыт намеренно — не восстанавливать workflow/ветку `gh-pages`.

## Ошибкоопасные места

- `src/domain/positionZones.ts` — построение зон в двух системах осей (вдоль линии мяча и в осях ворот для стандартов). Легко «смазать» зоны или сдвинуть смысл.
- `src/components/FieldView.tsx` — клип зон по треугольнику угла удара применяется только для прямых ударов; для угловых/навесов клипа быть не должно (иначе зона вырождается в серп).
- `src/sounds.ts` — звук по умолчанию выключен (`localStorage goalkeeper-sim:sound-on`), включается динамиком; AudioContext стартует по жесту пользователя.
- `public/sw.js` — при выпуске новой версии поднимать номер кэша, иначе у пользователей останется старая сборка.
- localStorage — все ключи с префиксом `goalkeeper-sim:`, прогресс по каждому игроку; не ломать формат (есть экспорт/импорт).
