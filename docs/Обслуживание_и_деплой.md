# Обслуживание и деплой — «Где стоять вратарю?»

Для технического специалиста, который развернёт, обновит или починит проект. Общий обзор архитектуры — в `docs/Обзор_проекта.md`.

## Кратко

- Статическое SPA (Vite + React + TypeScript). Бэкенда нет, базы нет, секретов нет.
- Прод: `https://keeper.anyatobolova.ru`, отдаётся веб-сервером **Caddy** с VPS Beget.
- Обновление = собрать локально (`npm run build`) и скопировать `dist/` на сервер в `/srv/keeper/`.

## Стек и требования

- Для сборки: **Node.js 20+** и npm (локально или в CI).
- На сервере: только статическая раздача через **Caddy** (уже установлен и обслуживает несколько сайтов). Отдельно ничего ставить не нужно — ни nginx, ни Node, ни Docker.
- Репозиторий: GitHub `AnyaTobolova/goalkeeper-position-simulator`, ветка `main`.

## Переменные окружения / секреты

Их нет. Это статический сайт: вся логика в браузере, прогресс — в `localStorage`. Файла `.env` в проекте нет и не требуется. Единственные «секреты» проекта — доступы к инфраструктуре (ниже), они в код и репозиторий не попадают.

## Локальная разработка

```bash
npm install

```

## Сборка

```bash
npm run build    # tsc + vite build -> папка dist/
npm run preview  # локально посмотреть production-сборку
```

Перед деплоем всегда: `npm run test` и `npm run build` должны пройти без ошибок.

## Деплой на сервер

Сборка копируется в `/srv/keeper/`. Старые ассеты с хешами в имени удаляются, чтобы не копились.

```bash
npm run build
ssh -i ~/.ssh/academy_vps root@62.113.111.4 'rm -rf /srv/keeper/assets /srv/keeper/index.html /srv/keeper/sw.js'
scp -i ~/.ssh/academy_vps -r dist/* root@62.113.111.4:/srv/keeper/
```

Caddy перечитывать **не нужно** — статика подхватывается сразу.

### Если меняли service worker (PWA-кэш)

При выпуске новой версии подними номер кэша в `public/sw.js` (`cacheName = "goalkeeper-sim-vN"`), иначе у пользователей может остаться старая версия. Заголовок `Cache-Control: no-cache` для `sw.js` уже настроен в Caddy.

## Проверка после деплоя

```bash
curl -sS https://keeper.anyatobolova.ru/ | grep -o 'index-[A-Za-z0-9_-]*\.js'   # версия сборки на сайте
curl -sS -o /dev/null -w "%{http_code}\n" https://keeper.anyatobolova.ru/         # ожидаем 200
```

Плюс открыть в браузере (лучше в режиме телефона): проходит уровень, зоны рисуются, звук включается динамиком.

## Откат к предыдущей версии

Бэкап статики отдельно не хранится — источник в git, сборка воспроизводимая. Чтобы вернуть предыдущую версию:

```bash
git log --oneline           # найти предыдущий рабочий коммит
git checkout <хеш>          # или git revert <плохой-хеш> в новой ветке
npm run build
# затем те же команды деплоя (rm + scp)
git checkout main           # вернуться на main после проверки
```

## Веб-сервер Caddy (если нужно менять раздачу)

- Конфиг: `/etc/caddy/Caddyfile`, отдельный блок `keeper.anyatobolova.ru` (root `/srv/keeper`, SPA-fallback, security-заголовки).
- HTTPS выпускается автоматически (Let's Encrypt).
- Порядок безопасного изменения (чтобы не уронить соседние сайты):

```bash
cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%F-%H%M%S)   # бэкап
# ... правка ...
caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile      # проверка
systemctl reload caddy                                                # именно reload, не restart
```

Блок keeper отдаёт security-заголовки: строгий `Content-Security-Policy` (только собственные файлы), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, HSTS; для `sw.js` — `Cache-Control: no-cache`.

## Частые проблемы и диагностика

| Симптом | Причина / что проверить |
|---|---|
| Сайт не открывается (не 200) | `systemctl status caddy`; занятость портов 80/443; DNS поддомена на Рег.ру. |
| Открывается старая версия | PWA-кэш: подними номер в `public/sw.js`, пересобери, задеплой; пользователю — обновить страницу. |
| Нет замка HTTPS | Caddy сам выпускает сертификат; проверить логи `journalctl -u caddy`, что домен резолвится на этот IP. |
| Упал соседний сайт после правок | Восстановить `Caddyfile` из бэкапа, `caddy validate`, `systemctl reload caddy`. |
| Горизонтальный скролл / вёрстка на телефоне | проверить в режиме мобильного viewport, править `src/styles.css`. |

## Безопасность (эксплуатация)

- Включить двухфакторную аутентификацию и уникальные пароли в кабинетах **Beget** и **Рег.ру** — это главный реальный риск (угон аккаунтов), а не «взлом сайта».
- SSH — только по ключу, вход root по паролю отключить.
- Секреты/ключи не коммитить (защищено `.gitignore`).
- У игры нет сбора персональных данных и сторонних скриптов — обязательств по 152-ФЗ не возникает.
