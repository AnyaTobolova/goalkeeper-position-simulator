# Этапы реализации проекта

Документ используется как рабочий чек-лист. Когда этап реально завершен и проверен локально, чек-бокс меняется с `[ ]` на `[x]`.

## Правила отметки готовности

- Чек-бокс ставится только после фактического завершения этапа.
- Для игровых механик этап считается завершенным после локальной проверки в браузере.
- Для документации этап считается завершенным после обновления ТЗ и сценариев.
- Если этап частично сделан, он остается без галочки, а детали фиксируются в подпунктах.
- При завершении этапа нужно обновлять этот файл в том же изменении, где завершена работа.

Безопасность (принятые решения, июль 2026):

- Вход/логин в игру не нужен: серверной логики и аккаунтов нет, прогресс и имена хранятся только в localStorage устройства, персональные данные на сервер не передаются.
- [x] Запрет индексации поисковиками: `public/robots.txt` (Disallow: /) + `<meta name="robots" content="noindex, nofollow">` - игра только для своих. Снять легко, если решение изменится.
- [ ] На VPS: вход по SSH-ключу, отключить вход root по паролю, включить автообновления безопасности; только nginx со статикой, без PHP/панелей/FTP.
- [ ] В nginx: security-заголовки (Content-Security-Policy: только собственные файлы; X-Content-Type-Options: nosniff; frame-ancestors 'none'; Referrer-Policy), HSTS после проверки HTTPS; для `sw.js` - Cache-Control: no-cache.
- [ ] Включить двухфакторную аутентификацию и уникальные пароли в аккаунтах Beget и Рег.ру (главный реальный риск - угон аккаунтов, а не «взлом сайта»).
- [ ] Периодически: `npm audit` и обновление зависимостей перед новыми релизами.
- При желании закрыть игру паролем - Basic Auth в nginx одной строкой (решается на сервере, код игры менять не нужно).
