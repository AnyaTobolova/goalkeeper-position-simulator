# Обзор проекта «Где стоять вратарю?»

Единый документ для быстрого понимания проекта: что это, как устроено, где что лежит, как разрабатывать и как задеплоено. Читать первым. Остальные документы — углублённые (ссылки в конце).

---

## 1. Что это и для кого

Обучающий 2D-симулятор для юного футбольного вратаря. Игрок видит эпизод атаки, перетаскивает вратаря в правильную позицию, разворачивает корпус к мячу и нажимает «Готов». Игра оценивает позицию по футбольной геометрии и даёт короткий тренерский разбор.

- **Аудитория:** ребёнок ~9 лет (сын владельца проекта) и его друзья по ссылке.
- **Статус:** личный проект без коммерции. Развёрнут и работает.
- **Главный принцип:** учить не «угадывать точку», а видеть ситуацию — где мяч, какой угол удара, где защитник, можно ли бить сейчас, куда сместиться до удара. Методическая правильность важнее всего.

## 2. Технологии

- **Vite + React 19 + TypeScript** — статическое SPA, без бэкенда.
- **SVG** — игровое поле, зоны, углы, фигуры (файл `src/components/FieldView.tsx`).
- **Web Audio** — синтезированные звуки без файлов (`src/sounds.ts`).
- **localStorage** — весь прогресс и настройки на устройстве. Сервер данные не хранит.
- **PWA** — service worker + manifest, устанавливается на телефон, работает офлайн после первой загрузки.
- **vitest** — юнит-тесты доменной логики.

Данные с сервера не запрашиваются: нет аналитики, рекламы, сторонних скриптов, аккаунтов и передачи персональных данных.

## 3. Как запускать (команды)

```bash
npm install        # установка зависимостей
npm run dev        # локальный dev-сервер (http://localhost:5173)
npm run test       # юнит-тесты (vitest, ~103 проверки)
npm run build      # production-сборка в dist/ (tsc + vite build)
npm run preview    # посмотреть production-сборку локально
```

## 4. Структура кода

Вся оценочная логика вынесена в `src/domain/` — это чистые функции без React, они и покрыты тестами.

**Доменный слой (`src/domain/`):**

| Файл | Назначение |
| --- | --- |
| `types.ts` | Все типы: `Level`, `PitchConfig`, `ScenarioType`, `ErrorType`, `EvaluationScore` и т.д. |
| `levels.ts` | Данные всех сценариев (56 базовых + 18 реакционных). Уровень = мяч, игроки, стартовая позиция, тексты, тип. |
| `presets.ts` | Пресеты полей и ворот (5v5, 7v7, 8v8, 9v9, 11v11, футзал, свои). |
| `scenarios.ts` | Определение типа сценария по данным уровня; сторона мяча; какие критерии показывать. |
| `positionZones.ts` | Построение зон допуска (зелёная/оранжевая/красная) в локальных осях: вдоль линии мяча или в осях ворот для стандартов. Масштаб глубины от размера ворот. |
| `geometry.ts` | Базовая геометрия: расстояния, углы, перевод проценты↔метры, «сколько ворот видит нападающий». |
| `evaluate.ts` | Главный алгоритм: `checkAnswer` и `evaluateGoalkeeper` — считают баллы по линии, глубине, ближнему углу, корпусу, стенке и выдают результат/ошибку. Здесь же `freeKickWallZone`, `resolveTimeoutResult`. |
| `feedback.ts` | Сборка тренерского разбора: критерии, тексты, визуальные подсказки — единообразно по типу сценария. |
| `variation.ts` | Вариации координат при повторах, включая зеркальные (лево↔право с зеркалированием текстов). |
| `badges.ts` | Бейджи за навыки и звание вратаря по числу закреплённых сценариев. |
| `rulesQuiz.ts` | Данные квиза по правилам вратаря (пас назад, руки, 8 секунд и т.д.). |

**UI (`src/`):**

| Файл | Назначение |
| --- | --- |
| `App.tsx` | Основной экран, состояние игры, все игровые циклы, меню, модалки. |
| `components/FieldView.tsx` | Отрисовка поля, зон, фигур, анимации удара с исходом. |
| `components/PlayerPanel.tsx` | Выбор/добавление/удаление игрока. |
| `components/SettingsPanel.tsx` | Формат поля/ворот, время реакции, показ размеров. |
| `components/StatsPanel.tsx` | Статистика ошибок, слабые места, бейджи. |
| `components/RulesQuiz.tsx` | Квиз по правилам. |
| `components/PenaltyShootout.tsx` | Мини-игра «Серия пенальти» (реакция). |
| `sounds.ts` | Синтезированные звуки (сейв, гол, удар, свисток, бейдж). |
| `storage.ts` | Чтение/запись localStorage. |
| `styles.css` | Все стили, включая адаптив под телефон. |

## 5. Игровые режимы

- **База** — 56 позиционных сценариев (угол удара, глубина, 1-в-1, защитник, пасы/отскоки, навесы, угловые, штрафные со стенкой, пенальти, выходы за спину защиты).
- **Реакция** — 18 сценариев: игроки без мяча → у одного появляется мяч → таймер (5/4/3 сек) → занять позицию. В части сценариев мяч уходит в пас во время отсчёта.
- **Тренировка дня** — ежедневная подборка из 10 ситуаций, серия дней подряд.
- **Марафон** — 10 случайных ситуаций без подсказок, очки (до 100 за ситуацию), рекорды по игрокам.
- **Слабые места** — повтор только ошибочных сценариев.
- **Серия пенальти** — мини-игра на реакцию: выбрать угол, куда летит мяч.
- **Правила вратаря** — квиз-карточки.

Экран итогов после спецсессий; бейджи и звания; несколько локальных игроков с отдельным прогрессом.

## 6. Как считается правильная позиция (методика)

Оценка — алгоритм, а не заранее нарисованные прямоугольники. Основные принципы (подробно — в методичке):

- Позиция строится от **линии мяч → центр ворот**; при боковом мяче сначала закрывается **ближний угол**.
- **Глубина** зависит от дистанции мяча и **масштабируется от размера ворот** (эталон — юниорские 5 м).
- **Корпус к мячу обязателен** для «Отлично» (иначе «Почти»).
- Стандарты (угловые, навесы, штрафные, пенальти) заданы целью **в координатах ворот** (`goalTarget`), поэтому не «плывут» при смене пресета поля.
- **Пенальти** — единственная ситуация по Правилам игры: до удара часть ноги на линии ворот.
- Зона стенки при штрафном считается геометрически (линия «мяч — ближняя штанга»).

Результаты: `Отлично` / `Почти` / `Нужно поправить` / `Опасно`. Ошибочные ситуации возвращаются на повтор.

## 7. Хранение данных (localStorage)

Все ключи с префиксом `goalkeeper-sim:`. Прогресс — по каждому игроку. Ничего не уходит на сервер.

- `players`, `active-player` — профили игроков и текущий.
- `progress:<id>` — прогресс игрока (попытки, ошибки, серии).
- `last-level:<mode>:<id>` — где остановился (отдельно База/Реакция).
- `day-streak:<id>`, `marathon-best:<id>`, `penalty-best:<id>` — рекорды режимов.
- `pitch`, `training-mode`, `reaction-time-seconds`, `show-dimensions`, `sound-on`, `onboarding-complete` — настройки устройства.

Перенос между устройствами — кнопки «Прогресс в файл / Загрузить из файла» в меню (раздел «Данные и установка»).

## 8. Инфраструктура и деплой

- **Адрес:** https://keeper.anyatobolova.ru (поддомен на Рег.ру).
- **Сервер:** VPS Beget, `62.113.111.4`, Ubuntu 24.04. На нём уже работают другие проекты владельца (n8n, supabase, api, app, academy) — их трогать нельзя.
- **Веб-сервер:** **Caddy** (не nginx!) — общий для всех сайтов, автоматический HTTPS (Let's Encrypt). Конфиг: `/etc/caddy/Caddyfile`, отдельный блок `keeper.anyatobolova.ru`.
- **Файлы игры на сервере:** `/srv/keeper/` (статическая сборка из `dist/`).
- **Доступ по SSH:** ключ `~/.ssh/academy_vps` (в `~/.ssh/config` хост уже настроен на этот IP). Файл `ssh.txt` в проекте — это публичный ключ, он в `.gitignore`.

**Как выкатить обновление:**

```bash
npm run build
ssh -i ~/.ssh/academy_vps root@62.113.111.4 'rm -rf /srv/keeper/assets /srv/keeper/index.html /srv/keeper/sw.js'
scp -i ~/.ssh/academy_vps -r dist/* root@62.113.111.4:/srv/keeper/
```

Caddy перечитывать не нужно — статика подхватывается сразу. Меняли `Caddyfile` — тогда `caddy validate` и `systemctl reload caddy` (именно reload, не restart, чтобы соседние сайты не падали).

**Security-заголовки** (в блоке Caddy): строгий Content-Security-Policy (только собственные файлы), `X-Content-Type-Options`, `X-Frame-Options`, HSTS; для `sw.js` — `Cache-Control: no-cache`.

**GitHub:** репозиторий `AnyaTobolova/goalkeeper-position-simulator`, ветка `main`. GitHub Pages закрыт (workflow и ветка `gh-pages` удалены) — игра переехала на свой домен.

## 9. Приватность и безопасность

- Игра закрыта от поисковиков (`robots.txt` + `noindex`), но доступна по прямой ссылке любому.
- Логин не нужен: нет сервера, аккаунтов и персональных данных.
- Главный реальный риск — угон аккаунтов **Beget** и **Рег.ру**: там нужны уникальные пароли и двухфакторная аутентификация.
- `.gitignore` защищает ssh-ключи от попадания в репозиторий.
